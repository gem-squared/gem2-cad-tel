# CAD Trust Engine Lite

**적산(Quantity Takeoff)을 위한 감사 가능한 평면도 분석 엔진**

*Designed and implemented by David Seo of GEM².AI*

## 🟢 라이브 데모

**[https://cad-tel.gemsquared.ai](https://cad-tel.gemsquared.ai)** — 브라우저에서 바로 확인 가능. PNG / JPG / PDF 도면을 업로드하면 검수 UI에서 결과를 볼 수 있습니다. 첫 OCR 호출 시 모델 로드로 1~2분이 걸릴 수 있습니다.

## 1. 문제

건축 도면 인식 결과는 곧바로 **자재 물량과 비용 판단**으로 이어집니다. 벽 하나를 잘못 인식하거나 치수를 잘못 산출하면, 그 오류가 자재 발주와 공사비 산정으로 그대로 흘러갑니다. 문제는 이런 실수 대부분이 시공 단계 전까지 드러나지 않는다는 점입니다.

일반 컴퓨터 비전 벤치마크가 요구하는 "더 많이, 더 정확하게 검출한다"는 목표만으로는 이 리스크를 다룰 수 없습니다. 시공 도메인에서 **확신에 찬 잘못된 숫자는 인식하지 못한 도면보다 큰 리스크**입니다. 자신 없이 침묵하는 결과는 검수자가 다시 볼 수 있지만, 자신 있게 틀리는 결과는 발주까지 흘러가고 나서야 드러납니다.

이 엔진의 존재 이유는 검출 정확도를 자랑하는 것이 아니라, 각 판단의 **근거·불확실성·검수 경로**가 함께 노출되는 신뢰 표면(trust surface)을 시공 도메인에 맞게 갖추는 것입니다. 이 엔진은 전문 견적사(quantity surveyor)의 판단을 대체하려는 시스템이 아니며, 견적사가 안심하고 검수·감사할 수 있도록 결과를 정직하게 노출하는 것이 목적입니다.

## 2. 해결 방식

이 엔진은 스키마 수준에서 네 가지 규범을 강제합니다. 각 규범은 라이브 데모에서 검수자가 직접 확인할 수 있는 형태로 드러납니다. 세부 구현 규칙은 공개하지 않습니다.

- **판단의 분리** — 모든 객체는 "무엇인가(type)", "형상(geometry)", "물리 치수(measurement)"에 대한 판단을 **독립적으로** 기록합니다. 하나가 확실하다고 나머지가 자동으로 확실해지지 않습니다. 검수 UI에서는 세 판단을 각각 시각적으로 구분해서 볼 수 있습니다.
- **강제하지 않는 판단** — 근거가 부족한 영역은 낮은 신뢰도로 밀어 넣지 않고 **명시적 거부(refusal)** 로 표시됩니다. 검수 UI에서는 이 거부 영역이 원본 도면 위에 오버레이로 나타나, 검수자가 "여기는 사람이 확인해야 한다"는 신호를 즉시 받습니다.
- **측정 안전 게이트** — 신뢰할 수 있는 스케일 기준이 확립되지 않은 도면에는 물리 단위(mm) 값이 결과에 나오지 않습니다. 픽셀 값은 진단용으로 남을 수 있지만, 스케일 근거 없이 mm로 변환되지 않도록 출력 계약이 잠겨 있습니다.
- **감사 가능성** — 실행 결과·판단 보류·정책 발동이 모두 감사 저장소에 남습니다. 검수자는 한 도면의 결과뿐 아니라 여러 실행에 걸친 오류·거부 패턴을 시간 축으로 조회할 수 있습니다.

전체 처리 흐름은 다음 한 줄로 요약됩니다.

> 평면도 입력 → 신뢰-인식 분석 → 검수 가능한 결과 + 구조화된 출력 + 감사 이력

## 3. 설계 원칙

이 엔진의 방향을 결정한 다섯 가지 원칙입니다. 내부 알고리즘·threshold·모델 선정 기준은 공개하지 않지만, 원칙은 공개합니다 — 검수자와 협업자가 이 시스템이 왜 이렇게 동작하는지 이해할 수 있어야 하기 때문입니다.

- **Refusal is a first-class output** — 거부는 침묵도 placeholder도 아닌 정식 출력입니다. 낮은 coverage는 받아들일 수 있지만, 자신 있게 틀리는 detection은 검수 파이프라인에 들어가서는 안 됩니다.
- **Evidence granularity is per-claim** — 한 객체에 대해 "무엇 / 형상 / 측정"을 각각 독립 판단합니다. 하나의 confidence 점수로 세 판단을 압축하면 trust surface가 무너집니다.
- **Physical units gate on scale evidence** — 스케일 기준이 독립적으로 검증되기 전에는 mm 값이 나오지 않습니다. 이 규칙은 관습이 아니라 스키마가 강제합니다.
- **Every uncertain claim is annotated** — 근거가 부족한 판단은 그 부족함의 종류(추정의 근거 또는 지식의 공백)를 함께 기록합니다. bare 불확실은 스키마 층에서 거부됩니다.
- **Provenance is enforced, not implied** — 학습·검증에 쓰이는 자산은 출처와 라이선스가 검증된 것만 사용합니다. 라이선스가 불명확한 source는 조용히 흡수하지 않고 명시적으로 제외됩니다.

## 5. 기술 스택 (범주 수준)

- **언어**: Python 3.11+
- **컴퓨터 비전 / OCR**: 검증된 오픈소스 CV + 다국어 OCR (한글 + 라틴 문자 지원)
- **스키마·타입 계약**: Pydantic v2
- **검수 UI**: Streamlit
- **감사 저장소**: SQLite (표준 라이브러리)
- **PDF 처리**: rasterization 후 페이지 단위 처리
- **배포**: Docker 기반 컨테이너

특정 알고리즘의 조합·임계값·후처리 규칙·모델 선정 기준·스케일 판정 방식 등은 공개하지 않습니다.

## 6. 최소 로컬 설치 (기술 검증 목적)

라이브 데모가 주 경로입니다. 로컬에서 직접 확인하려면:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .
streamlit run ui/app.py
```

- 브라우저에서 `http://localhost:8501`에 접속해 도면을 업로드합니다
- 첫 실행 시 OCR 모델 다운로드로 시간이 소요됩니다
- 배포 스크립트·컨테이너 구성·리버스 프록시 설정은 공개 저장소에 포함하지 않습니다

## 7. 라이선스 / IP

- **소스코드 라이선스**: `Proprietary` (`pyproject.toml` 기준)
- corpus 자산은 각 항목별 공개 라이선스(CC-BY, CC-BY-SA, public 등)를 별도로 기록합니다. 소스코드 라이선스와 corpus 라이선스는 구분됩니다
- 이 저장소는 **capability 공개 + recipe 보호** 전략을 취합니다: capability는 데모와 공개된 출력 계약으로 검증 가능하지만, 내부 recipe·threshold·routing은 공개하지 않습니다
